# AstraNotes Requirement Traceability Matrix

This matrix traces three selected requirements from business need through design, implementation, and verification evidence.

| Requirement ID | Requirement | Source | Design / Model Trace | Implementation Trace | Verification Trace | Status | Gap / Next Action |
| --- | --- | --- | --- | --- | --- | --- | --- |
| RTM-001 | Users must not be able to create notes without a title. | `project-requirements.md` Functional Requirements 1: Note Creation requires `title` and states empty notes shall not be submittable. | `prisma/schema.prisma` `Note.title String` is required; `Note` stores title separately from CRDT state. | `src/app/api/notes/validation.ts` rejects missing, non-string, or blank titles with `400` and `Title is required`; `src/app/api/notes/route.ts` calls validation before `prisma.note.create`. | `src/app/api/notes/validation.test.ts`; `tests/unit/notes-validation.test.ts`; `src/app/api/notes/route.test.ts`; `tests/integration/notes-route-lifecycle.test.ts`. Add a direct missing-title test if stricter evidence is required. | Partially verified | Existing validation implements the requirement, but current tests emphasize valid title normalization and related invalid payloads. Add an explicit test for omitted and whitespace-only `title`. |
| RTM-002 | Users must be able to permanently delete their notes in the database. | `project-requirements.md` Reliability & Governance 1: deleted data shall be hard-deletable with audit records; default retention is 30 days unless administrative override is authorized. `backlog.md` also references soft-delete or permanently purge notes from the dashboard. | `prisma/schema.prisma` uses cascading relations from `Note` to `NoteBlob`, `Share`, and `ActivityLog`; this supports hard deletion of note-owned rows when implemented. | Current `src/app/api/notes/[id]/route.ts` `DELETE` only soft-deletes by setting `status: 'DELETED'` and writing an activity log. No hard-delete endpoint or purge job exists in the current code. | `src/app/api/notes/[id]/route.test.ts` and `tests/integration/notes-route-lifecycle.test.ts` verify soft deletion only. No permanent deletion test exists. | Not implemented | Add an authorized hard-delete/purge flow that physically removes the note and dependent database records after retention or administrative override, preserves required audit evidence, and includes unit/integration tests. |
| RTM-003 | Users must be able to use keyword search on their notes. | `project-requirements.md` Functional Requirements 3: system supports full-text search across `title`, `content_plain`, and `tags` for non-encrypted notes. | `prisma/schema.prisma` stores searchable fields as `Note.title`, `Note.tags`, and `NoteBlob.contentPlain`; `Note.status` supports excluding deleted notes. | `src/components/note-room-launcher.tsx` provides client-side keyword filtering across note title, category, tags, and content preview. No server-side `/api/notes` search route is currently implemented. | No dedicated keyword search tests found. | Partially implemented | Add server-side search with pagination and deleted-note exclusion, backed by appropriate Postgres indexes or full-text search. Add tests for title, content, tag keyword matches, encrypted-note exclusion, and deleted-note exclusion. |

## Summary

- `RTM-001` is implemented and needs one sharper negative test for full traceability.
- `RTM-002` is currently a gap because the app supports soft deletion, not permanent database deletion.
- `RTM-003` has UI-level keyword filtering but needs API/database-backed search to satisfy the full project requirement.
